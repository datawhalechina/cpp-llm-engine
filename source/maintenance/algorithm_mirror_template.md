# 算法镜像模板

算法镜像先暴露数学步骤或状态推进，再进入 C++ 的内存、所有权和错误处理。它通常使用 10–30 行 Python 风格代码，也可以使用状态图或步骤表；除非页面明确提供运行脚本，否则代码块只表达算法，不承诺可直接执行。

## 适用条件

满足以下任一条件时可以增加算法镜像：

- 三层以上循环或状态迁移掩盖了核心算法；
- shape、mask、offset、block 映射或量化 block 解码难以从 C++ 资源代码中直接看清；
- 需要先固定 reference 顺序，再讨论 SIMD、CUDA、融合或调度优化。

Loader、Storage 所有权、Benchmark 和 Profiling 默认使用文件布局、对象关系和测量表，不机械添加 Python。

## 固定结构

算法镜像放在对应正文问题内部，不默认单独分页，并按以下顺序出现：

1. 用一段话写明输入、输出和镜像省略的工程内容。
2. 给出 10–30 行由本教程维护的 Python 风格代码、状态图或步骤表。
3. 紧接一张“算法动作 → C++ 位置 → 验证重点”映射表。
4. 在页面验证部分给出固定 shape、数值、状态或失败路径。

推荐映射表：

| 算法动作 | C++ 对象或源码 | 验证重点 |
| --- | --- | --- |
| 输入怎样进入循环 | 具体接口或文件 | shape、dtype、初始状态 |
| 核心更新 | 具体函数或 kernel | 数值、mask、offset 或状态变化 |
| 输出怎样提交 | 具体对象或测试 | 输出 shape、错误状态、资源归属 |

## 表达规则

- 变量名优先对应正文概念和 shape，例如 `query_token`、`block_id`，不照抄外部项目内部缩写。
- 镜像只保留决定结果的数学和控制流，省略 allocator、线程、日志、网络和生产级错误恢复。
- 省略内容必须在镜像前说明，不能让学习者误以为 Python 与 C++ 功能完全等价。
- 不复制 nano-vLLM、vLLM、SGLang 等项目的大段源码；镜像由本教程重写并维护。
- 优化页面必须保留 reference 镜像，不能用 SIMD/CUDA 代码替代算法定义。

## 可执行参考

只有独立数值参考确实有价值时才增加可执行 Python：

- 脚本放在 `code/<module>/reference/`，不进入 `src/`；
- 默认 CMake、CTest 和全局回归不安装或调用 PyTorch；
- 生成的 fixture 记录 seed、shape、dtype、容差和参考来源；
- C++ 测试读取已提交的小型 fixture，验证命令说明怎样重新生成。

## 审核清单

- [ ] 镜像比对应 C++ 更容易看清算法
- [ ] 输入、输出和省略项明确
- [ ] 每个关键动作能定位到 C++
- [ ] 固定证据能验证镜像与实现一致
- [ ] 没有形成第二套 Runtime 或默认 Python 依赖
