# Teaching Assets 算法镜像、框架对照与图片规则

教学资产只在文字难以直接表达算法推进、工程差异或对象关系时使用。它们必须减少理解成本，并与当前代码和测试证据一致，不能只承担装饰作用。

## 1. 算法镜像

算法镜像先暴露数学步骤或状态推进，再进入 C++ 的内存、所有权和错误处理。适合 Attention、采样、调度、缓存映射等控制流；Loader、Storage、Benchmark 和 Profiling 通常优先使用布局表、对象关系或测量记录。

镜像默认嵌入对应正文，使用 10–30 行 Python 风格伪代码、状态图或步骤表，不建立独立 Python Runtime。只有需要生成 fixture 或执行数值对照时才创建 `code/<module>/reference/` 脚本。

镜像必须给出输入 shape 或状态、核心循环或状态转移、输出、对应 C++ 对象和验证重点。不得复制外部项目大段源码，也不能省略会影响结果的 mask、位置、容量和终止条件。

## 2. 成熟框架对照

章级对照卡回答五个问题：本章教学实现了什么；主要对照哪些框架；成熟系统额外处理什么；教学与生产实现差在哪里；从哪个稳定入口继续阅读源码。

章节只保存稳定概念和少量入口，具体版本、易变源码路径和核验日期集中到 `reference/ecosystem/` 的项目卡。正文仅在工程差异直接影响当前设计时加入短段“工程坐标”，不为每页重复完整框架背景。

对照必须区分算法骨架、教学实现和生产工程。项目名称相同、类名相似或文档宣传不能替代源码与官方资料证据。外部项目用于回答工程问题，不替代教程 C++ 主线。

## 3. 图片职责

绘图前先写出图片要表达的一句话，并核对节点、连线和代码对象。优先级是：表格能讲清时用表格；短状态流可以用纯文本；稳定且复杂的结构再制作 SVG。

章节 intro 默认一张主图，同时表达章节位置和本章输入、处理、输出。算法步骤、内存布局、状态机和性能时间线进入对应正文细节图，不与主图竞争入口。

图片必须满足：

- 节点是正文已经解释或紧接着解释的概念，中文概念为主，代码名作为补充。
- 箭头真实连接源节点与目标节点；顺序、依赖、数据流和状态转移不混用同一种线。
- 并列实现画成分支，不画成前后执行；默认、可选和规划路径使用一致视觉规则。
- 已实现、外部参照和规划能力明确区分，不能把接口草图画成可运行能力。
- 文字在常见桌面和移动宽度下可读，无裁切、遮挡、悬空连线和过大箭头。
- 易变类名、文件路径、性能数字和阶段任务不进入长期主图。

## 4. 视觉与版式

同一张图使用有限的颜色表达固定含义，不能只为丰富画面增加颜色。节点间距、圆角、字号和箭头尺寸保持一致；标题说明图片回答的问题，不重复页面标题。

图表前先给阅读方法和必要背景，图表后不增加新的关键结论。SVG 必须包含可访问的 `title` 与 `desc`，并在浏览器中人工检查，不能只依据 XML、Markdown 构建或链接检查判断正确。

## 5. 证据与更新

图片或对照卡中的对象、状态和“已完成”结论必须能定位到代码与测试。公共接口、章节编号、执行顺序、默认路径或实现状态变化时，同步复核正文、代码 README、框架对照和相关 SVG。

提交前至少确认：语义正确；箭头连接正确；中英文使用一致；规划能力未写成完成；源码入口可达；浏览器渲染无裁切；文档链接和站点构建通过。
