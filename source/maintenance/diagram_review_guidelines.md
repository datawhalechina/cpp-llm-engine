# Diagram Review 图片审核规则

本规则用于教程中的 SVG、Mermaid、流程图、状态图和架构图。图片必须帮助学习者建立可验证的关系，不能只承担装饰作用。

## 1. 先核对语义

绘图前先写出图片要表达的一句话，并把节点、连接和代码实现逐项对应。

- 数据流箭头表示数据从源对象进入目标对象；
- 状态箭头表示允许发生的状态迁移；
- 引用线表示多个对象指向同一资源；
- 依赖箭头表示前一个产物是后一个步骤的输入；
- 并列实现使用分支，不画成前后执行；
- 残差路径从被保留的数据节点出发，进入明确的加法节点。

无法用一句话解释的连线应删除或重新定义。

## 2. 连接必须闭合

每条有向连接都要同时满足以下条件：

1. 线段从源节点边界或可见分叉点开始；
2. 箭头尖端落在目标节点边界；
3. 起点和终点不能悬在两个节点之间；
4. 连线不能被节点覆盖，也不能停在节点中心；
5. 箭头颜色应与对应线段一致。

分叉和汇合需要显式表达：

- 一条数据分成多路时，在源节点或公共线段上放置可见连接点；
- 多路数据相加时，每条路径分别连接加法节点；
- 多个对象共享资源时，每个对象分别指向资源，不在空白处合并成一条线；
- 两个后端产生同一结果时，先分支到后端，再从后端连接统一输出。

## 3. 路径必须可追踪

学习者应能从任一输入沿线走到对应输出。

- 主路径优先保持从左到右或从上到下；
- 旁路和残差使用直角折线，并与主路径保持间距；
- 连线不得穿过文字、节点或其他箭头；
- 交叉无法避免时，应改变布局，不能依赖颜色猜测；
- 同一语义使用固定颜色，颜色不能成为唯一识别手段；
- 标签靠近对应路径，但不能压在线段或箭头上。

## 4. 文字与层级

- 中文概念优先，代码名作为括号或小号文字补充；
- 标题说明结论，不使用“内容概要”“架构关系”等空泛名称；
- 节点文字描述对象或动作，避免只写抽象层名；
- 一张主图只表达章节位置和核心流程；
- 详细内存布局、状态机和后端分层拆到正文图片；
- 正文不能依赖颜色、悬停或放大后才能解释图片。

## 5. 与实现保持一致

图片提交前必须对照当前代码和测试：

| 检查对象 | 核对内容 |
| --- | --- |
| 执行顺序 | 与实际函数调用顺序一致 |
| 输入输出 | shape、dtype、状态和所有权一致 |
| 分支 | 默认路径、可选路径和并列实现没有画反 |
| 已实现状态 | 不把规划能力画成已完成能力 |
| 验证结果 | 图中的固定数值或状态可由脚本复现 |

容易随版本变化的源码类名、文件路径和性能数值不要放进主图。

## 6. 渲染审核

SVG 必须包含 `viewBox`、`<title>`、`<desc>`，并使用浏览器完成最终审核。ImageMagick 可能使用不同字体，只能作为辅助检查。

至少执行：

```bash
xmllint --noout source/assets/diagrams/<name>.svg
google-chrome --headless --no-sandbox --disable-gpu --hide-scrollbars \
  --window-size=1200,680 \
  --screenshot=/tmp/<name>.png \
  file:///absolute/path/to/source/assets/diagrams/<name>.svg
npm run docs:check-links
git diff --check
```

浏览器截图需要人工完成四次追踪：

1. 从每个输入追踪到输出；
2. 从每个分叉点追踪所有分支；
3. 从每条旁路追踪到汇合节点；
4. 在不阅读正文的情况下复述图片结论。

XML、链接和构建检查只能证明文件有效，不能证明连接关系正确；人工视觉审核不可省略。

## 7. 提交前清单

- [ ] 图片只承担预定职责
- [ ] 每条箭头连接源节点和目标节点边界
- [ ] 分叉点、汇合点和残差加法节点可见
- [ ] 没有悬空、反向、穿字或被遮挡的连线
- [ ] 中文概念优先，代码名为补充
- [ ] 章节位置、执行顺序和实现状态与代码一致
- [ ] 1200px 浏览器截图可读
- [ ] SVG 语法、文档构建和差异检查通过
