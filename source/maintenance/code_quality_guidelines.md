# Code Quality 代码质量与审核规则

本规则适用于 `code/` 下的 C++、CUDA、测试和构建代码。审核最终回答：结果是否正确，失败是否安全，接口是否诚实，证据是否独立。

## 1. 审核顺序

1. 从正文提取已承诺的输入、输出、数据变化和失败行为。
2. 检查公共接口的 shape、dtype、布局、设备、所有权、生命周期和错误方式。
3. 沿入口检查索引、状态变化、资源申请释放和失败后的对象状态。
4. 检查正常、失败、边界、状态和跨章测试是否提供独立证据。
5. 确认示例、脚本和 CMake 实际构建并执行声明的 target。
6. 运行局部测试、严格警告、适用的运行时错误检测器（Sanitizer）、默认回归和发布验收。
7. 回到文档和图片，删除代码或测试不能证明的能力声明。

先审职责和接口，再审命名与格式，避免在错误架构上优化代码风格。

## 2. 正确性与数据安全

- 公式、shape、stride、offset、索引和状态转换与正文一致。
- 元素数、字节数和索引计算在运算前检查整数溢出。
- 浮点测试按误差选择绝对或相对容差；只有可精确表示的结果使用精确相等。
- SIMD、量化、融合和 CUDA 与独立 reference 或固定 golden 比较。
- 指针解引用前检查可验证的空值、容量、设备和布局；无法验证的条件写入公共接口。
- CPU、CUDA 和 pinned host memory 不隐式互换。

## 3. 所有权、资源与并发

- 拥有资源的对象使用 RAII；View、引用和非拥有指针明确生命周期。
- stream、event、handle、workspace、KV block 和请求槽位在正常、取消和失败路径成对释放。
- 写入前完成校验；要求失败原子性时先写临时结果，成功后提交。
- 请求、缓存事务和服务生命周期只能进入一个终态，重复完成或取消不能重复释放。
- 共享可变状态说明线程模型，并验证竞争、取消和终态交错。

## 4. 接口、职责与可读性

- 公共接口说明 shape、dtype、布局、设备、所有权、生命周期、失败行为、同步和 fallback。
- 可恢复输入、资源和设备错误返回 `Status`；便捷包装可以抛异常，但不能丢失原因。
- 禁止静默复制、连续化、设备迁移、同步和 CPU fallback。
- 章节通过公开 target 和头文件连接，不包含其他章节私有 `.cpp`。
- 抽象对应真实变化点；单一实现不提前叠加多层 Factory、Manager 或 Adapter。
- 主流程能沿入口阅读，类型和函数使用具体名称，教学 reference 也不能省略安全校验。
- 文件头用 3–5 行说明对象或场景、输入输出、关键限制和验证入口；行内注释只解释布局、生命周期、溢出和失败恢复。

## 5. 测试与证据

| 层级 | 证明内容 | 最低要求 |
| --- | --- | --- |
| unit | 局部公式、索引或状态函数 | 固定输入、边界和失败输入 |
| component | 单章对象协作 | 公开接口、结果和失败原子性 |
| contract | 跨实现共同遵守的行为 | reference 与候选实现共用用例 |
| integration | 相邻章节真实交接 | 使用公开类型和 target |
| real_model | 权重、Tokenizer 和模型执行 | 固定模型、配置和结果 |
| e2e | 请求到终态的完整链路 | 生命周期、输出、指标和资源释放 |

一个测试块验证一个可命名行为。测试不能调用被测实现生成期望值；随机测试记录 seed、shape、dtype 和容差。CUDA 编译、真实设备执行和 CPU 数值对照分别记录，不能互相替代。

## 6. 性能与路线证据

正确性通过后再 benchmark，定位瓶颈后再优化。前后结果使用相同 workload、构建类型、线程数、设备、warmup 和统计方法，并记录环境与原始数据。热路径中的分配、复制、锁、同步和设备传输必须可识别。

| 路线 | 审核重点 | 必要证据 |
| --- | --- | --- |
| A 教学闭环 | 算法和数据变化能否直接阅读 | 小尺寸输入、reference 和失败路径 |
| B 真实 CPU | 是否接入真实资产和跨章接口 | 集成测试、真实模型或固定 golden |
| G GPU | 设备资源、异步执行和 CPU 对照 | 编译、设备执行和数值对照 |
| M 多模态 | 新输入是否在 embedding 后复用 Runtime | 预处理、投影、拼接和请求生命周期 |

## 7. 问题等级与两轮审核

| 等级 | 判断标准 | 处理要求 |
| --- | --- | --- |
| P0 | 错误结果、越界、泄漏、数据竞争，或测试误判 | 合并前修复并增加回归 |
| P1 | 生命周期不安全、职责错误、绕过公共接口、文档与实现不一致 | 当前批次修复或撤回声明 |
| P2 | 覆盖不足、失败定位困难、重复实现或隐式行为 | 记录位置、owner 和验收标准 |
| P3 | 命名、注释、局部结构和格式问题 | 不扩大范围时修复 |

章节审核分两轮：建设审核先冻结标准、形成完整问题清单并修正；冷启动验收不沿用第一轮清单，从文档声明重新反查接口、相邻章节、失败输入、资源释放和证据。第一轮改变过设计或实现时，不能同时充当最终验收。

收敛要求：没有未处理 P0/P1；P2 已修复或登记 owner 与验收标准；文档、图片、代码 README、接口和测试使用同一概念；未执行的模型、CUDA、网络和性能验证被记录。

## 8. 自动门禁

编译警告、运行时错误检测器、CTest、默认回归和发布验收提供不同证据，但都不能替代职责、生命周期和证据独立性的人工审核。CPU 章节可运行统一局部门禁：

```bash
npm run test:cpp-quality -- code/chapter04_attention \
  '^(chapter04_attention_test|chapter02_tensor_attention_integration_test)$'
```

脚本默认运行严格警告和 UBSan；环境支持时可增加 `CPP_LLM_ENABLE_ASAN=1`。CUDA 仍需单独记录 `nvcc` 编译、设备执行和 CPU 对照。完整测试注册和证据层级见 [`code/testing/README.md`](../../code/testing/README.md)。

代码质量通过要求：局部测试、严格警告和适用的运行时错误检测器通过；默认回归与受影响发布验收通过；文档、接口、实现和证据一致。单章过程记录保存在本地，只有跨章节长期规则进入本文件。
