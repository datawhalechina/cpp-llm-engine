# Tutorial Writing 教程写作与页面模板

教程页面先于源码被阅读。文字先用输入、输出、数据变化和失败现象解释原理，再映射到实现和验证；文件名和类名不能代替首次解释。

## 1. 内容分层

| 位置 | 负责回答的问题 |
| --- | --- |
| 根 README / USAGE | 项目是什么，从哪里开始，选择哪条路线 |
| Foundation | 需要补哪些 C++、构建、测试和 CUDA 前置能力 |
| Chapter00–10 正文 | 原理是什么，数据怎样变化，为什么这样设计 |
| `code/<chapter>/README.md` | 按什么顺序阅读、运行和验证源码 |
| Guides | 怎样组合稳定章节形成学习或复现任务 |
| Reference | 到哪里查术语、公式、实验和框架坐标 |
| Maintenance | 怎样长期保持定位、写作和实现一致 |

章节正文不记录 Task 编号、当前完成率、建设优先级或迁移过程。计划可以引用稳定章节，但调整计划不要求改写正文。

## 2. 模板适用范围

所有学习内容都要先解释问题，再连接代码；“已实现”声明必须能定位到测试或实验。页面结构按职责选择，不为版式一致补造内容。

| 内容 | 使用方式 |
| --- | --- |
| Foundation | 能力选择、正文与练习映射、单题验收；不强制框架对照和真实模型 |
| Chapter00 | 环境、外部工具、模型、首次推理和排错；以 llama.cpp 基线为主 |
| Chapter01–02 | 使用章节导读、正文和代码 README；扩展只在有真实实现时加入 |
| Chapter03–10 | 使用完整导读、正文、代码 README、框架坐标和分层验证 |

## 3. 章节导读

`intro.md` 默认只使用三个二级标题：

1. `本章导读`：说明上游输入、本章处理、输出和引擎位置。
2. `开始学习`：给出 3–7 个正文页面、源码入口和每步观察对象。
3. `验证与下一步`：列出命令、成功条件、本章新增能力和下一章交接。

导读默认只有一张主图，同时表达章节位置和输入、处理、输出。A 是小尺寸教学闭环，B 是真实 CPU 路径，G 是 GPU 后端扩展，M 是多模态输入扩展；没有代码或证据时只能标为扩展坐标。总结收口到导读，不再新建重复的 `summary.md`。

## 4. 正文页面

一个页面解决一个技术问题，按学习顺序组织：

1. **原理与数据变化**：从场景进入输入、输出、公式、shape、布局、状态或生命周期。
2. **设计与实现映射**：解释当前选择、代价、C++ 对象和调用顺序。
3. **验证与下一步**：用固定输出、失败路径、测试或实验判断结果。

关键实现页必须回答：问题怎样出现；数据怎样变化；为什么采用当前设计；哪些对象实现它；学习者能观察什么。所有权、布局、临时结果提交、CPU/GPU 替换点、错误恢复和资源释放不能只用“保持契约”概括。

正文开头不堆学习目标和设计清单。叙述负责解释原理，列表收束约束、失败模式和步骤；命令通常放在验证阶段。

## 5. 代码 README

代码 README 面向已经读过正文、准备进入源码的学习者，默认使用四个二级标题：

1. `代码架构`：输入、关键对象、所有权、失败提交和上下游接口。
2. `阅读顺序与资产`：按理解顺序列文件、观察重点和对应测试。
3. `运行与验证`：给出根目录命令、预期输出和证据层级。
4. `扩展入口`：只列真实存在的 GPU、多模态、模型或下一章连接点。

代码架构是必选内容。README 不重复公式推导、框架背景、维护状态或完整目录树。

## 6. 正文、源码与练习

- 先用中文概念、公式、形状或状态完成解释，再给类型名和函数名。
- 关键实现页靠前链接具体源码；源码入口服务阅读顺序，不把目录清单当作学习路径。
- Python 仅作为短算法镜像或 fixture 生成工具，不成为默认 CMake/CTest 依赖。
- 正文解释“为什么和怎样工作”；练习说明“修改什么和怎样验收”，两边不复制题目清单。
- 源码文件头、注释和实现质量由[代码质量规则](./code_quality_guidelines.md)统一约束。

## 7. 算法镜像、框架对照与图片

教学资产只在文字难以直接表达算法推进、工程差异或对象关系时使用，必须降低理解成本并与代码和测试一致。

- **算法镜像**：使用 10–30 行 Python 风格伪代码、状态图或步骤表暴露数学步骤和状态推进。镜像写明输入 shape、核心循环、输出、对应 C++ 对象和验证重点，不复制外部项目大段源码，也不建立第二套 Runtime。
- **框架对照**：章级落点说明教学实现、生产系统的额外工作、二者差距和继续阅读入口。稳定概念留在章节，易变源码坐标、版本和核验日期集中到 `reference/ecosystem/`；Chapter01–10 每章只维护一份完整对照。
- **图片**：intro 默认一张主图表达章节位置和输入、处理、输出；算法步骤、内存布局、状态机和性能时间线放入对应正文。表格能讲清时不用图，短状态流优先纯文本。

绘图前先写出图片要表达的一句话。节点使用正文已解释的中文概念，代码名作为补充；箭头真实连接源和目标，并列实现画成分支；默认、可选、规划和已实现路径可区分。SVG 需要 `title`、`desc`，并人工检查字号、裁切、遮挡、悬空连线和移动宽度下的可读性。

图片和框架卡中的“已实现”必须能定位到代码与测试。公共接口、章节编号、执行顺序或能力状态变化时，同步复核正文、代码 README、对照和相关 SVG。

## 8. 语言与提交检查

- 中文正文优先；API、命令、文件名和稳定专名保留原文，首次出现说明作用。
- 标题表达问题、动作或对象，不使用“概览、进一步理解、这一层、这一页”等空泛指代。
- 删除重复分类、连续否定式边界说明、复述式总结和维护者口吻。
- 图表前给出阅读方法，图表后不追加新的关键结论。
- 页面标题层级与内容量匹配，原理、设计、源码和验证按学习顺序出现。
- 源码链接、图片、命令、预期输出和能力声明与当前实现一致。
- 提交前执行文档结构、风格、Reference 和链接检查，并运行 `git diff --check`。
