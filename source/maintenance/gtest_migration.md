# Google Test 迁移预案

本文仅供维护人员评估测试框架迁移，不进入学习者导航。

## 触发条件

只有某个模块明显需要共享 fixture、参数化测试、更细过滤或标准 CI 输出时，才考虑从当前轻量 harness 迁移到 Google Test。测试数量增加本身不构成迁移理由。

## 迁移范围

第一阶段只选一个有明确需求的模块，同时处理其 `tests/`、`CMakeLists.txt`、代码 README 和测试契约登记。其他模块保持原有入口，`ctest` 继续作为统一执行命令。

## 执行顺序

1. 引入 GTest 依赖并固定离线/在线获取策略。
2. 将现有命名测试映射为 `TEST` 或 `TEST_F`。
3. 保留 benchmark 逻辑和输出格式，不把性能测量混入 correctness test。
4. 用 `ctest` 验证新旧入口行为一致。
5. 最后更新学习者页面中的实际测试命令。
