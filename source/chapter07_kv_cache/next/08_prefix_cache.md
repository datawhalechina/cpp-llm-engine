# 07.8 从请求独占缓存扩展到前缀复用

当前缓存按请求独占物理块：两个请求即使拥有相同 prompt，也会分别计算并保存 K/V。前缀缓存进一步把“已经计算过的词元前缀”建立索引，让后续请求引用匹配块，并只计算未命中的后缀。

## 前缀复用增加哪些对象

| 对象 | 回答的问题 |
| --- | --- |
| 前缀索引 | 新请求与哪些已缓存词元匹配 |
| 共享块引用计数 | 一个物理块何时仍被请求使用 |
| 锁定状态 | 调度和执行期间哪些块不能淘汰 |
| 淘汰策略 | 空闲块不足时先回收哪些未使用前缀 |
| 命中长度 | Prefill 可以从哪个位置继续计算 |

普通 BlockTable 只描述一个请求的逻辑位置到物理块映射。支持共享后，多个页表可以引用同一个只读前缀块；请求写入自己的后缀前，不能修改共享块。

## Radix 索引与调度是什么关系

Radix 树按词元序列组织公共前缀，适合返回最长匹配长度和对应缓存节点。最长前缀匹配调度可以优先选择命中更多缓存的请求，但调度顺序与缓存索引仍是两个对象：Chapter07 提供匹配、引用和回收，Chapter08 决定何时执行哪个请求。

```text
token sequence
  -> prefix match
  -> shared read-only blocks
  -> private writable suffix
```

## 实现前必须固定的契约

本章可运行的 `KvBlockPool` 只支持请求独占块，没有跨请求前缀索引、共享块引用计数和淘汰策略。因此上面的 Radix 路径是用于理解生产扩展的设计对照，不是 `chapter07_kv_cache` 的可运行结果。

若要将该路径变成可运行能力，验证必须同时证明：相同前缀只计算一次、共享块不会被覆盖、任一请求结束不会提前释放共享块、容量压力下只淘汰未锁定前缀、未命中请求保持原有结果。

Mini-SGLang 和 SGLang 的入口可查阅 [Mini-SGLang 生态卡](/reference/ecosystem/mini_sglang) 与 [SGLang 生态卡](/reference/ecosystem/sglang)。
