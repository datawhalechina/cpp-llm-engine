# 02.5 张量与视图框架对照：数据不动，观察方式改变

本章的 1–4 维 `reshape`、按轴 `slice` 和 `transpose` 共享一份 CPU 存储。对照成熟实现时，先检查维数、形状、步长、偏移和底层存储，再判断操作是否真的零拷贝。

## 对象映射

| 教程对象 | ggml / `llama.cpp` | vLLM 运行时 | 阅读重点 |
| --- | --- | --- | --- |
| 共享存储（`storage_`） | 张量数据缓冲区 / 后端缓冲区 | 缓存张量和执行缓冲区 | 谁拥有底层内存 |
| `shape`、`stride`、`offset` | `ggml_tensor` 元数据 | 块表、槽位映射、张量视图 | 逻辑索引怎样落到物理位置 |
| `reshape` | 变形/视图图算子 | 模型执行器中的形状变换 | 是否要求连续布局 |
| `slice` | 视图/偏移操作 | KV 块或词元窗口寻址 | 子窗口是否复制数据 |
| `transpose` | 置换/转置图算子 | Q/K/V 轴变换 | 交换轴后是否连续 |
| `contiguous()` | 连续化/复制图算子 | 模型执行器中的布局整理 | 何时分配新缓冲区 |
| `TensorContract` | 后端的形状/类型检查 | 工作进程/后端输入契约 | 错误在哪一层被拒绝 |

## 教学实现与生产实现

本章使用连续 CPU Float32 存储；视图可以通过步长表达非连续布局，算子入口再决定是否要求连续。

| 本章可验证对象 | 成熟系统继续增加 | 学习顺序 |
| --- | --- | --- |
| 1–4 维变形、按轴切片和按轴转置 | 广播、任意维数和内存格式 | 先覆盖 LLM 常用布局 |
| 形状/步长/偏移契约与显式连续化 | 更多内存格式和异步复制 | 不隐藏潜在复制成本 |
| CPU 生命周期与越界检查 | GPU 分配器、CUDA 流和异步释放 | 设备生命周期留给计算后端主线 |
| 线性窗口切片 | 分页 K/V、前缀共享和写时复制 | 缓存与调度分别由 Chapter07/08 承接 |
