# 03.6 从循环次数理解矩阵乘法成本

矩阵乘法会生成 `M × N` 个输出元素，每个元素需要沿 K 维累加。三重循环因此执行约 `M × N × K` 次乘加，通常写作 `O(MNK)`。

## 用两个规模建立直觉

`[2,3] × [3,2]` 产生 4 个输出，每个输出累加 3 项，一共计算 12 个乘积。这个规模适合手算，但无法体现计算库的优势。

`[256,256] × [256,256]` 需要约 1678 万次乘加。CPU 和 GPU 执行的数学工作量没有变化，实际耗时却会受到缓存、向量指令、并行度和启动成本影响。

| 因素 | 观察重点 |
| --- | --- |
| 访问顺序 | 连续读取能否提高缓存和显存带宽利用率 |
| SIMD / Tensor Core | 一条指令能够同时处理多少元素 |
| 分块 | 同一批数据能否在高速存储中重复使用 |
| 后端启动成本 | 小矩阵的计算时间是否小于函数或 Kernel 启动时间 |

## 复杂度相同不代表耗时相同

CPU 三重循环、分块 GEMM 和 cuBLAS 都执行矩阵乘法，因此渐进复杂度相同。优化的目标是减少访存等待、提高并行度和复用硬件指令，而不是改变输出矩阵。
