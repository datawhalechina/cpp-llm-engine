# 03.6 建立复杂度直觉

MatMul 的基本工作量随 `M × N × K` 增长。复杂度不会因为代码写法改变，但缓存、向量化和 GPU 并行会显著改变实际耗时。

## 从三重循环看计算量

输出共有 `M × N` 个元素，每个元素沿 K 维完成乘加，因此基础工作量是 `O(MNK)`。小矩阵适合手算和定位错误，大矩阵需要高性能计算后端。

CPU 参考实现的价值是索引关系清楚、结果稳定，而不是与优化库竞争速度。过早把分块、SIMD 和并行循环混入参考实现，会同时增加数值、布局和性能三类排查成本。

## 复杂度与实际性能的区别

相同 `O(MNK)` 可以有不同运行时间：

| 因素 | 影响 |
| --- | --- |
| 访问顺序 | 缓存命中与内存带宽 |
| SIMD / Tensor Core | 每条指令完成的运算量 |
| 分块 | 数据是否能在高速缓存中复用 |
| 后端启动成本 | 小矩阵时库调用或内核启动占比 |

因此 Chapter03 先固定正确性和计算后端接口，Chapter07/08 再用性能基准与性能剖析判断优化是否值得保留。

## 验证与衔接

能够从 `M、N、K` 解释三重循环次数，并区分“算法工作量”和“计算后端实际耗时”，即可进入 [`真实推理后端对照`](./07_runtime_backend_bridge.md)。
